## 1. なぜ作り直すか

- iPad 専用アプリで、Android 版は別にある（`../LifeManagement`）。Flutter の利点（クロスプラットフォーム）を使っていない。
- ユーザーが求めているものはすべて Apple 専用の機能：
  - iPadOS 26 の **Liquid Glass**（タブバー、シート、ボタン、メニューまで純正の見た目）
  - **PencilKit** とペンの遅延の最小化
  - Apple Pencil のスクイーズとダブルタップ
  - 通知（チャイム）
- ユーザーの不満：「左端じゃま」「UI がださい」「せっかく iPad なんだから Liquid Glass」。左サイドバーは使わないこと。
- 途中で「Flutter の外枠だけネイティブにする（案③）」も検討したが、フル Swift のほうが単純で効果も大きいので、こちらに決めた。

## 3. 目指す構成

- **SwiftUI**。iPad 専用（`TARGETED_DEVICE_FAMILY = 2`）。対象 OS は §8 で確認する（iPadOS 26 なら Liquid Glass を全面的に使う。古い OS も対象にするなら `#available` で分ける）。
- **`TabView`**（iPadOS 26 では上部に浮かぶ Liquid Glass のタブバーになる）：今／スケジュール／統計／ボード。
  **サイドバー表示は使わない**（`sidebarAdaptable` にしない）。
- 各タブは `NavigationStack`。タイトルとツールバーのボタン（スケジュールの「プリセット」「追加」など）は標準の Liquid Glass ボタンにする。
  編集はシート（`.sheet`）、確認は `confirmationDialog`、時刻は `DatePicker`。
- **ボード**：`UIViewRepresentable` で `PKCanvasView` を包む。タブバーは残す。必要ならボードのタブではタブバーを隠すかどうかを調整する。
- **ロジックは Swift Package（`StudyCore`）に分ける**。UIKit や SwiftUI に依存しない純粋な Swift にする。
  `swift test` で Windows でも Linux でもテストできるようにするため（下記 §5）。
- 状態管理：`@Observable` のモデル（Flutter 版の `StudyController` に相当）。時刻は差し替えられるようにする（テスト用）。
- 保存：`Application Support/study.json`。**Flutter 版と同じ形式で読み書き**して、データをそのまま引き継げるようにする。
  安全に書き込む（一時ファイルに書いてから置き換える）。読めない部分は捨て、元のファイルは別名で残す（Flutter 版と同じ）。
- チャイム：`UNUserNotificationCenter`。前面表示中も音とバナーを出す。予約は内容から作る ID で差分だけ登録する。
  起動時・アプリに戻ったとき・編集時・日付の切り替わり時に計画し直す。
- 日本語のみ。

## 4. 環境と制約

- 開発機は **Windows**。iOS アプリのビルドとシミュレータは使えない。
  **アプリのビルドは GitHub Actions（macOS）だけ**で行う。SwiftUI のプレビューも見られない。
- Xcode のプロジェクトファイルは手書きしない。**XcodeGen（`project.yml`）を CI 上で実行して生成する**。
- CI の方針（今の `.github/workflows/ios.yml` を参考に）：
  - Actions は SHA で固定、権限は `contents: read`
  - Xcode のバージョンを明示して、**iOS 26 SDK** でビルドする（Liquid Glass に必要）
  - 署名なしでビルドして、`Payload/` に入れて zip し、IPA を artifact としてアップロードする
  - `StudyCore` の `swift test` と、アプリのテスト（`xcodebuild test`、シミュレータ）も回す
- 配布：無料の Apple ID と Sideloadly で iPad に入れる。**有料の entitlement は使えない**（App Groups、Push、Family Controls などは不可）。
  **アプリ拡張（ウィジェットなど）は今回作らない**（無料アカウントでは App ID の数に制限があるため）。
- Swift 6 の厳密な並行性チェックを前提にする。API は存在を確かめてから使う（ローカルで iOS SDK の型チェックができないため）。
- コミット：メッセージの最後に Co-Authored-By などの帰属行を付ける。**push はユーザーの明示的な指示があるときだけ。**
- やり取りは日本語で。ユーザーは結果を iPad の実機で確認する。

## 5. ローカルでテストする（Windows）

- Swift for Windows を入れれば（`winget install Swift.Toolchain`。Visual Studio Build Tools が必要）、
  `StudyCore` は `swift build` と `swift test` をこのPCで実行できる。
  導入できない場合は、CI の Linux または macOS のジョブで `swift test` を回す。
- Flutter 版のテスト（`test/study/*.dart`）を XCTest か Swift Testing に移す。同じ入力で同じ結果になることを確認する。

## 6. 進める順番（段階ごとにコミット。各段階で CI が通り、実機で動く状態にする）

1. **土台**：リポジトリの中に Swift 版のフォルダを作る（例：`Swift/`。`project.yml`、`App/`、`Packages/StudyCore/`）。
   新しい CI ワークフローを作り、空の TabView アプリが署名なし IPA になるところまで。
   Flutter 版のワークフローは、作り直しが終わるまで残してよい（ユーザーと相談）。
2. **StudyCore**：ロジックとテストを移植して、`swift test` を通す。
3. **データとモデル**：`study.json` の読み書き（Flutter 版との互換を含む）、日付の切り替わり処理、プリセットの自動適用。
4. **今** の画面。
5. **スケジュール**の画面（編集、並び替え、削除と元に戻す、ポモドーロ、プリセット）。
6. **統計**の画面。
7. **ボード**（既存の Swift を流用し、Flutter との連携部分を外す）。
8. **チャイム**（通知の許可、差分登録、前面表示）。
9. 実機で確認し終えたら、Flutter 版のファイルとワークフローを削除する（**ユーザーの了承を得てから**）。

## 11. HIG（ヒューマンインターフェイスガイドライン）に合わせて決めたこと

日本語版 HIG を参照して決めた。理由も HIG の該当項目。

- **Liquid Glass はコントロール層だけ**（タブバー、ツールバー、ボードの浮きボタン、確認トースト）。今の画面と統計のカードはコンテンツ層なので、グループ背景色の普通のカードにした（マテリアル）。
- **外観はシステムに従う**（ダークモード：アプリ固有の外観設定を作らない）。独自色はライト・ダーク・コントラストを上げる、の各場合を用意した（`BlockStyle`）。Flutter 版の「ダーク基本」はやめた。戻す場合は `StudyApp` で `.preferredColorScheme(.dark)` を付ける。
- **取り消し／やり直し**はシステムの UndoManager に登録する（⌘Z、3本指ジェスチャ、トーストの「取り消す」）。取り消せる操作には確認アラートを出さない（アラート）。「すべて削除」だけ確認する。トーストは VoiceOver 中は自動で消えない（アクセシビリティ：時間制限を避ける）。
- **シート**：左に「キャンセル」、右に「保存」（confirm ロール）。変更があるときはスワイプで閉じない（シート）。
- **通知の許可**は起動時ではなく、最初にチャイムを予約するときに求める。オフのときは画面で知らせ、設定へのリンクを出す。ロック画面でプレビューを隠しているときは「勉強と休憩の切り替え」と表示する（通知）。
- **グラフ**は Swift Charts（VoiceOver のオーディオグラフ、選んだ日の値を表示、達成日はチェックでも区別）。
- **タブ**：`tabBarOnly`、塗りのシンボル、最後に開いていたタブを復元（起動）。メニューバーに ⌘N（ブロックを追加）と ⌘1〜4（タブ切り替え）。
- **アイコン**：Flutter のロゴが残っていたので、帯表示をモチーフにしたオリジナルに差し替えた（デフォルト・ダーク・淡色）。
